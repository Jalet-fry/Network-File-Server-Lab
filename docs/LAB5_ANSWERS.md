# Ответы на вопросы к Лабораторной работе №5

## 1. Объяснить работу программы traceroute
Программа `traceroute` предназначена для определения маршрута следования данных в сетях TCP/IP.
**Механизм работы:**
1. Отправляется серия пакетов (ICMP Echo Request или UDP на случайный порт) с полем TTL (Time-to-Live) равным 1.
2. Первый маршрутизатор на пути уменьшает TTL до 0, отбрасывает пакет и отправляет отправителю ICMP-сообщение "Time Exceeded" (тип 11, код 0). `traceroute` фиксирует IP-адрес этого маршрутизатора и время отклика.
3. Процесс повторяется с TTL=2, 3 и т.д., пока пакет не достигнет узла назначения.
4. Узел назначения при получении пакета с TTL > 0 не отбрасывает его, а обрабатывает. Если использовался ICMP Echo Request, он ответит "Echo Reply" (тип 0). Если использовался UDP, он ответит "Destination Unreachable / Port Unreachable" (тип 3, код 3).
5. На основе полученных ответов выстраивается цепочка IP-адресов маршрутизаторов.

## 2. Объяснить механизм действия smurf атаки. Какие угрозы она несет? Способы защиты?
**Механизм:**
Атакующий отправляет ICMP Echo Request (пинг) на широковещательный адрес (Broadcast) сети. При этом в IP-заголовке адрес источника (Source IP) подменяется (spoofing) на IP-адрес жертвы.
Все узлы в сети, получившие широковещательный запрос, отправляют ICMP Echo Reply на адрес жертвы.

**Угрозы:**
*   **Усиление (Amplification):** Один пакет атакующего порождает N ответов от узлов сети (где N - количество хостов в сети), что лавинообразно увеличивает нагрузку на канал и процессор жертвы.
*   **DoS (Denial of Service):** Жертва оказывается залита трафиком, который она не запрашивала, что приводит к отказу в обслуживании.

**Способы защиты:**
*   **На маршрутизаторах:** Запрет трансляции направленных широковещательных пакетов (directed broadcast).
*   **На хостах:** Настройка ОС таким образом, чтобы она не отвечала на ICMP-запросы, отправленные на широковещательные адреса.
*   **Фильтрация:** Использование Ingress/Egress фильтрации для блокировки пакетов с поддельными IP-адресами отправителя на границах сети.

## 3. Объяснить назначение полей заголовка протокола IP
*   **Version (Версия):** 4 бита. Указывает версию протокола (4 для IPv4).
*   **IHL (Header Length):** 4 бита. Длина заголовка в 32-битных словах (минимум 5, т.е. 20 байт).
*   **Type of Service (TOS):** 8 бит. Параметры приоритета и качества обслуживания (QoS).
*   **Total Length:** 16 бит. Общая длина пакета (заголовок + данные).
*   **Identification:** 16 бит. Уникальный идентификатор пакета, используется при фрагментации.
*   **Flags:** 3 бита. Управление фрагментацией (Don't Fragment, More Fragments).
*   **Fragment Offset:** 13 бит. Смещение фрагмента относительно начала данных исходного пакета.
*   **TTL (Time to Live):** 8 бит. Время жизни пакета (максимальное число хопов). Предотвращает бесконечное зацикливание.
*   **Protocol:** 8 бит. Код протокола следующего уровня (1=ICMP, 6=TCP, 17=UDP).
*   **Header Checksum:** 16 бит. Контрольная сумма только для заголовка.
*   **Source IP Address:** 32 бита. IP-адрес отправителя.
*   **Destination IP Address:** 32 бита. IP-адрес получателя.
*   **Options:** Необязательные поля для диагностики, безопасности и т.д.
