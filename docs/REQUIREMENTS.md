# ✅ Чек-лист соответствия требованиям ЛР

## Общие требования
- [x] **Работа в реальной сети:** Проверено (Windows + Termux).
- [x] **Чистота кода:** Функции короткие, атомарные (одно действие = один метод).
- [x] **Кросплатформенность:** Работает на Windows и Linux (Android/Termux) без изменений кода.
- [x] **Стабильность:** Сервер не падает при отключении клиентов.

## ЛР №1: TCP и передача файлов
- [x] **Команды:** ECHO, TIME, LS, EXIT реализованы.
- [x] **Границы сообщений:** Решено через буферизацию до символа `\n`.
- [x] **Докачка:** Поддержка `offset` через `RandomAccessFile.seek()`.
- [x] **OOB Data:** Передача прогресса через `socket.sendUrgentData()`.
- [x] **Битрейт:** Скорость выводится в конце каждой сессии.

## ЛР №2: Reliable UDP
- [x] **Надежность:** Собственные механизмы ACK и Retries.
- [x] **Скорость:** Быстрее TCP в 1.5+ раза за счет окна и NIO.
- [x] **Скользящее окно:** Реализована пачечная отправка (Window Size 200).
- [x] **Оптимальный буфер:** 1400 байт (обоснование: Ethernet MTU 1500).

## ЛР №3: Мультиплексирование
- [x] **NIO Selector:** Обслуживание многих клиентов в одном потоке.
- [x] **Неблокируемость:** Команды не прерывают передачу файлов.

## ЛР №4: Пул потоков (Вариант 5)
- [x] **Динамика:** Инициализация Nmin (2), расширение до Nmax (10).
- [x] **Таймаут:** Лишние потоки завершаются через 60 секунд простоя.
- [x] **Защита accept:** Использована синхронизация (`synchronized`) для параллельного вызова.
