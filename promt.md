Ты — ведущий системный архитектор и сетевой инженер. Мы ведем проект по курсу СПОиРС (Сети и параллельная обработка информации) в рамках лабораторных работ №5, 6, 7 и 8. Лабораторные работы 1–4 уже сданы и приняты. 

### 1. АРХИТЕКТУРНЫЕ И АКАДЕМИЧЕСКИЕ ТРЕБОВАНИЯ
- Язык разработки: Kotlin (JVM) с низкоуровневой сетевой обвязкой через JNA (C/POSIX libc для Linux и WinSock2 ws2_32 для Windows).
- Кроссплатформенность: Код должен компилироваться и выполняться без изменений на Windows и Linux (Fedora/Ubuntu). Никаких `#ifdef` / платформенных ветвлений в бизнес-логике — все платформенные различия инкапсулированы внутри системных оберток (`NativeNet.kt`).
- Качество кода:
  * Принцип единственной ответственности (SRP).
  * Максимальная сложность функции: 10–15 атомарных действий.
  * Длина любой функции/метода: строго до 60 строк.
- Сетевое взаимодействие: Реализовано без сторонних тяжелых фреймворков.

### 3. ТРЕБОВАНИЯ К ЛАБОРАТОРНЫМ РАБОТАМ (5–8)
- Лабораторная работа №5 (Raw Sockets, ICMP, Traceroute, Smurf-атака):
  * Параллельный Ping нескольких узлов на сырых сокетах в многопоточном режиме. Для предотвращения перехвата чужих ответов потоки обязаны использовать `MSG_PEEK` (`recvfrom` с флагом `MSG_PEEK`), проверять ICMP ID / Sequence, и лишь при совпадении считывать пакет окончательно.
  * Traceroute: Инкремент TTL (от 1 до max), внедрение Timestamp в payload пакета, вычисление точного RTT по приходу ICMP Type 11 (Time Exceeded) и фиксация финиша при ICMP Type 0 (Echo Reply).
  * Smurf-атака (IP Spoofing): Формирование сырого IP-заголовка (`IpHeader.kt`), подмена адреса источника (Source IP) на IP жертвы (Windows: 10.220.155.14) и рассылка эхо-запросов. Демонстрация в Wireshark на Windows.
  * ВАЖНЫЕ ОСОБЕННОСТИ ЛР5:
    1) Windows блокирует подмену Source IP на уровне ядра Winsock (отправка с подменой возможна только из Linux/WSL/Fedora).
    2) Для честной ручной передачи заголовка IP ядру Linux через `IP_HDRINCL` сокет должен быть создан с типом `IPPROTO_RAW` (255), а не `IPPROTO_ICMP` (1).
    3) Маршрутизаторы/точки доступа часто режут Directed Broadcast (10.220.155.255). Для гарантированного теста в Wireshark пакеты можно слать напрямую на целевой IP.
    4) Обязателен лог возвращаемых кодов `errno` из системных вызовов `sendto` и `setsockopt`.

- Лабораторная работа №6 (P2P Чат: Broadcast + Multicast):
  * Одноранговый чат без выделенного сервера.
  * Автоопределение активного интерфейса, маски и широковещательного адреса (`NetworkDiscovery.kt`), игнорирование виртуальных интерфейсов (Hyper-V, VirtualBox).
  * Режимы: Broadcast и Multicast (группа 239.0.0.1).
  * Команды: `/mode <b|m>`, автообнаружение пиров (`HELLO`-маяки раз в 3 сек), `/list`, бан/игнорирование хоста (`/ignore <id/ip>`), самостоятельный выход (`/leave`, `/exit`).

- Лабораторная работа №7 (MPI Матрицы: P2P Point-to-Point):
  * Распределенное перемножение матриц большого размера (800x800+).
  * Детерминированное установление TCP-соединений: ранг `i` подключается к узлам с меньшим рангом, и принимает подключения от больших.
  * Реализация двух режимов: Blocking (`MPI_Send` / `MPI_Recv`) и Non-blocking (`MPI_Isend` / `MPI_Irecv` + `Wait`). Демонстрация заметного прироста производительности в non-blocking режиме за счет перекрытия вычислений и сетевой передачи. Математическая верификация результата.

- Лабораторная работа №8 (MPI Коллективные операции и MPI-IO):
  * Разделение коммуникатора на группы (`Communicator.createGroup`).
  * Коллективные операции: `bcast`, `reduce`, `gather`.
  * MPI-IO: Параллельная работа с общими файлами `matrixA.bin` и `matrixB.bin` через позиционированный ввод/вывод (`RandomAccessFile`, методы `readAt` / `writeAt` со смещением по rank) и запись в `result_group_X.bin`.
